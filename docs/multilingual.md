# 多言語の音節解析（v0.4.1）

ボーカル音声・旋律MIDI・原文歌詞を使い、元の単語の何番目の音節が発音されているかを20ms刻みで推定する。
日本語・英語・ドイツ語・フランス語・中国語（普通話）・韓国語・スペイン語・イタリア語に対応し、同じ行に混在できる。
コード・再生画面・依存関係は正式な `utalign` パッケージに含まれ、試作フォルダやサンプル固有辞書は不要。

## 利用方法

既存のコマンドをそのまま使える。既定の `auto` は、注釈を除いた歌詞にLatin文字・Hangulがあれば音節解析へ切り替える。
漢字だけの歌詞は日中の言語判定を使う。言語指定・読み指定を与えた場合も音節解析へ進む。
日本語だけの歌詞は従来のモーラ解析を使い、`--alignment-mode multilingual` で音節解析を明示選択できる。

```sh
utalign align --audio vocal.wav --lyrics lyrics.txt --midi vocal.mid \
  --languages ja,en,de --out out --work work

utalign utavista-align --audio vocal.wav --lyrics lyrics.txt --midi vocal.mid \
  --languages ja,en,de --out-json timing.json --work work --progress-json
```

- `--languages`: 曲で使う言語コードをカンマ区切りで指定。省略時は8言語。
- `--alignment-mode auto|multilingual|japanese`: 自動切替・多言語音節・従来の日本語モーラ解析。
- `--midi-tracks`: 歌唱旋律トラックの番号。伴奏を含むMIDIでは指定を推奨。
- `--midi-offset`: 音声時刻−MIDI時刻（秒）。省略時は既存のオンセット相関で推定。
- `--search-band`: 最初のCTC時刻を中心とするMIDI対応探索の範囲（既定10秒）。
- `--readings`: 日本語の読み上書き。音節解析でも日本語の箇所へ適用する。

音節解析は日本語**音素**モデルを使う。既定の `japanese-hubert-base-phoneme-ctc-v4` が対応する。
かな文字モデル・starオプションとの組み合わせは明示的なエラーにする。

Webではプロジェクトの「歌詞の言語と音節」で方式・言語・MIDIオフセットを設定する。
解析後は単語ごとの音節ボタン、MIDI対応、弱い音声支持の表示、解析JSONの保存が使える。

## 言語・近似読みの補助指定

短語や漢字のみの区間は言語判定が曖昧な場合がある。Webの言語ヒントは1行ずつ `fr: Bonjour` の形式。
CLIの `--language-hints hints.json` は次の形式（`line` は1始まり、`char_start` は0始まりのUnicodeコードポイント位置）：

```json
{"spans":[{"text":"Bonjour","language":"fr"},{"text":"你好","language":"zh","line":3}]}
```

カタカナの正確な転写ではなく、音声との照合に使いやすい近似音を使う。
原語の単語・音節IDは別に保持するので、`out → キャウ` でも `out` の1音節として扱う。
Webの歌唱の近似読みは `knock out = ノッ / キャウ`。単語間を `/`、単語内の音節を `|` で区切る。
CLIの `--proxy-readings readings.json` は次の形式：

```json
{"spans":[{"text":"knock out","syllables":[["ノッ"],["キャウ"]]}]}
```

位置指定を省略すると同じ原文の全出現に適用する。元の単語数・音節数を変える指定や重複は拒否する。
補助指定なしでも各言語のG2Pから近似音を生成する。サンプルの読みを本体へハードコードしていない。

## 時刻とJSONの意味

多言語の `result.json` は `schema: utalign-result/2`、`timing_unit: syllable`。
`words`、`syllables`、原文位置、原語の発音仮説、近似読み、音素区間、母音核時刻、MIDI音符ID、支持度を保存する。
既存の文字エクスポータ用に `chars` / `moras` / `lines` も保持する。多言語時の `moras` は音節の互換ビューであり、モーラ数ではない。

MIDI割当は音声尤度を参照した動的計画法で求め、そのMIDI区間の前140ms〜後100msに全音素を制約してCTC整列する。
1音符に最大3音節、1音節に最大8音符のメリスマと余分なMIDI音符のスキップを扱う。歌詞の音節を削除しない。
成立する経路がなければエラーにし、制約を外した結果へ暗黙に切り替えない。音高照合はまだ使わない。

`start` は先頭音素の開始、`nucleus_start` は母音核の開始、`acoustic_end` は音素列の末尾。
表示用の `end` はMIDIの保持時間も使い次の音節開始までに制限するため、独立に検出した発声終了ではない。
`acoustic_support` は正解確率ではなく、0.02未満を `low_support` と表示する。

UTAVISTAの `lyrics-timing/1.0` は従来の構造を維持し、各wordへ `syllables` の追加情報を付ける。
外国語の綴りの各文字は `timingBasis: word_envelope` として同じ単語区間を共有する。音節の時刻を文字数で等分しない。
音節拡張を読まないUTAVISTAクライアントは外国語を単語単位で表示する。音節自体の詳細は `result.json` と追加フィールドに残る。

## 歌詞入力の扱い（原文・解析表記・未解決の診断）

- 原文の歌詞は書き換えない。読み・言語判定は別の解析用表記で行い、すべての位置は原文のコードポイント位置で返す。
  解析用表記の変更は NFC（`か`＋結合濁点→`が`）、半角カナ→全角（`ｶﾞ`→`ガ`）、全角英数字→半角、異体字セレクタの統合だけ。
  `①`・`㍑`・`™` などは NFKC で読み替えず、記号のまま残す。変更箇所は `result.json` の `normalization` に残る。
  NFC は結合文字の並べ替えを含む正準合成で、正準等価な表記（`a`＋´＋̣ と `a`＋̣＋´）は同じ解析表記になる。
  解析文字と原文位置は多対多（並べ替えで離れた位置をまとめる・U+0344 のように 1 文字が 2 つの結合文字に分かれる）で、
  原文の文字はそれを含む解析文字がすべて読まれたときだけ「読まれた」とみなす。言語ヒントは書記素や並べ替えた結合文字の途中で切れない。
- 基底文字の無い結合文字（行頭・空白や句読点の後の結合濁点や ´ など、半角 `ﾞ` 単独も含む）は黙って無視せず `orphan_mark` として位置付きで報告する。
  絵文字の異体字セレクタ・キーキャップ（U+20E3）・肌色修飾子は発音しない表示用の文字として扱う。
- 行区切りは CRLF・LF・CR・U+2028/U+2029 など（Python の `splitlines` と同じ）を、解析・ヒントの `line` 指定・診断の行/列・
  結果の `lines`/`chars[].line`・UTAVISTA の phrase で共通に使う。改行文字自体は原文のまま残す。
- 有効にしていない言語・文字体系で書かれた歌詞（例: `languages=en` で `あ`）は、位置付きの `language_not_enabled` として報告する。
- 音節の近似読み（proxy）も歌詞と同じ文脈付きのモーラ規則で検査し（先頭の `ー` など）、元の歌詞の位置と proxy 側の原因を
  `proxy_reading_invalid` として報告する。`ノッ`・`キャウ` のような複数モーラで 1 音節の近似読みはそのまま使える。
- 日本語は連続した日本語部分全体でモーラを作り、`ー`・`ッ`・`ン` を直前の音節へ付ける。形態素の境界で音節をリセットしない
  （`かッと` と `かっと`、`しンじる` と `しんじる` は同じ音節になる）。表示用の単語は、音節が形態素をまたぐときだけ結合する。
  空白・句読点・行頭の後の `ッ`・`ン` は独立した音節として残す。前に音の無い `ー`、音素を持たない読みはエラーにする。
  日本語モーラ方式でモデルが `ッ`/`ン` の音素を持たない場合も、同じ連続部分の直前の音にだけ畳み、空白・句読点・改行の向こうの音は借りない（エラーにする）。
- 数字、辞書に読みの無い漢字（`髙` など）、未対応の文字は、どちらの解析方式でも黙って除かず、行・列・理由付きのエラーにする。
  括弧・タグ・`©` 行の注釈は両方式で同じく歌わない文字として扱う。日本語モーラ方式では英字・ハングルもエラーになる（auto / multilingual を使う）。
- 読みを持つ記号は歌うかどうか・どう読むかが曖昧なので、読みを作らず `symbol_needs_reading` として位置付きで報告する。
  対象は通貨記号（`¥ $ € ＄` など Unicode の Sc）、文字様記号 U+2100–U+214F（`℃ ™ № ℓ`）、`% ％ ‰ & ＆ @ ＠ ° ∞`、
  囲み・組文字の CJK 記号（U+3200–U+33FF、`㍑`）。歌う場合は読み上書き（例: `℃ ど`）、歌わない場合は括弧の注釈にする。
  句読点・絵文字・矢印など、これ以外の記号は意図的に歌わない文字として扱い、診断しない（すべての Unicode 記号を判定するわけではない）。

### 読み上書き（`--readings`）

1 行に `表記 読み` を書く。読みはかな。原文の歌詞は書き換えず、指定した読みを黙って表記どおりの読みへ戻すことはない。

- `表記 よみ`（`|` 無し）は表記全体の読み。1 文字の表記はその文字の読み（`髙 たか`、`2 ふた`）。
  複数文字の表記で文字ごとの読みが決まらないとき（数字・英字・記号を含む `100 ひゃく`・`LOVE らぶ`・`LINE らいん`、
  モーラ数が表記と違うかな `かな き`・`すーん い`、按分で読まれない漢字が残る場合）は、全モーラを表記全体に属させる。
  その文字は同じ区間（`timingBasis: word_envelope`）を共有し、文字ごとの発音開始は作らない。
  UTAVISTA（`lyrics-timing/1.0`）のルビは 1 文字ごとの `char.ruby` で、取込側は文字単位でしか表示しないため、
  表記全体の読みをどの 1 文字に付けても誤った表示になる。そのためこの文字にはルビを出さない（先頭文字への集約・複製・按分をしない）。
  読み全体は `result.json` の moras（従来方式）・syllables の `moras`（`envelope: true`、多言語）に残り、結果の chars には
  `ruby_omitted` を、`meta.warnings` にはその旨を記録する。ルビが必要なら `|` で 1 文字ずつの読みを指定する（例: `2人 ふた|り`）。
  かなだけでモーラ数が同じ表記は 1 モーラずつ、漢字を含む表記は
  従来の送り仮名・漢字の按分（`split_estimated`）で全文字が読まれるときだけそれを使う（この 2 つは従来どおり文字ごとのルビを出す）。
- `表記 よ|み` は 1 文字ずつの読み（`言葉 こと|ば`、`カヽ か|か`）。`|` の区切り数は表記の文字数と同じにする。
  区切り数が違う・空の読み・かな以外の読みは、表記の位置で `reading_override_unmappable` のエラーにする。
- かな・漢字だけの表記は、形態素の区切りにそろった位置で適用する（1 形態素でも `か|な` のように複数形態素でもよい）。
  形態素の途中（より長い語の一部）には適用しない。数字・英字・記号などを含む表記は形態素分割に関係なく適用するが、
  英字・ハングル・数字で始まる/終わる表記は同じ種類の文字が隣に続く位置では一致しない（`ME` は `HOME` に、`2` は `12` に、
  `I` は `In` に掛からない）。大文字・小文字は区別する（`I` は `Hi` の `i` に掛からない）。
- 助数詞などを含めて読ませるときは句全体を指定する（例: `夜に2人` には `2人 ふた|り` → ヨルニフタリ）。`2 ふた` のように
  数字だけを指定した場合、隣の `人` の読みは辞書のまま（推測しない）。
- 上書きの読みと表記の境界は発音のまとまりを切らない（`OK おっけ` で `OKー` → ケー、`2 に` で `2っ` → ニッ）。
  空白・句読点・行頭の後の `ー`・`ッ`・`ン` の扱いは従来どおり。
- 音節解析では、上書きは日本語の読みなので `ja` が有効なときだけ使う。`ja` を有効にしていないのに上書きが掛かる箇所は、
  別の言語を黙って有効にしたり上書きを捨てたりせず、位置付きの `language_not_enabled` にする。
  同じ箇所に言語ヒントがあればヒントが優先する（`en: LINE` と `LINE らいん` → 英語の発音）。
  上書きの表記に続けて書かれた漢字だけの部分（`第1章` に `1 いっ` のときの `第`・`章`）は日本語として読むが確認済みとは扱わず、
  その部分の位置で `language_diagnostics`（`basis: readings_override_context`）に残す。
- 漢字だけの連続部分の中に、かな・漢字の上書き表記が形態素単位で現れる場合（`世界 せ|かい` で `中国世界`・`世界人民`）:
  連続部分全体が上書き表記の並びなら（`日本|世界` に `日本`・`世界` の両方を指定）日本語の読み上書きとして読む。
  一部だけのときは、自動判定が日本語なら上書きを使い、日本語以外（中国語など）なら上書きを黙って捨てて中国語で読むことはせず、
  単語全体の言語ヒント（`ja: 中国世界` か `zh: 中国世界`）を求める `reading_override_language_ambiguous` のエラーにする。
  `ja` が無効なら `language_not_enabled`。単語全体の `zh` ヒントがあれば中国語が優先する。形態素の途中にしか一致しない表記
  （`日本|世界` の中の `本世`）は適用しない。

### 言語ヒント・ルビ・音素

- 言語ヒントは単語全体に掛ける。周囲と同じ言語のヒントは読みを変えない。単語の途中を別言語へ切るヒントは位置付きのエラーにする。
  `々`・`〆`・`ー` は日本語の表記の手掛かりとして扱う。漢字だけの語の自動判定（日中）は変えず、推定であることを
  `language_diagnostics`（行・列付き。件数は単語ではなく区間の数）と `meta.warnings` に残す。漢字読みの按分推定も `split_estimated` として出力に残す。
- 音節の近似読み（proxy）の `text` は言語ヒントと同じ解析用表記で照合し（`LOVE` は `ＬＯＶＥ` に一致）、書記素の途中では切らない。
- 音響モデルの語彙でモーラ全体を表せない読み（`ゔ` の無いかな語彙や `v` の無い音素語彙での `ヴァ`）は、一部の音だけを残さず
  `no_model_phones` として位置付きで報告する。語彙にある音素への子音の分解（`ts` → `t s`）と `ー` の直前への統合は従来どおり。
- UTAVISTA 出力のルビは各漢字に属するモーラから作る（`待って` → 待: ま）。結合濁点・半角濁点は基底文字と同じ区間を持つ。
  音節内の文字の区間は書記素ごとの等分で、文字ごとに測定した時刻ではない。各音節の `moras` に読みと原文位置を残す。

## 検証と制限

v0.4.1はeSpeak NGをアンインストールした環境で確認した。既存の日英独サンプルは387単語・751音節を出力し、
v0.4.0との原文位置・単語内音節の対応を維持した。751音節中748音節の開始時刻が一致し、差の中央値・90パーセンタイルは0ms。
最大差は `creators` 内の220msであり、旧版・新版どちらが正解かは手動の正解ラベルなしには判断できない。
114音節は支持が弱い（旧版113）。全音節を出力したことは全時刻の正しさを保証しない。
UTAVISTA形式への変換は105行・177空白区切り語・1136文字で、自己検査エラー0件。

保存済みの8言語の合成読み上げを新しいG2Pで再解析し、18音節すべてを出力した。
新たな音声合成やeSpeak呼び出しは行っていない。合成器の音素イベントとの差は中央値28.2ms、最大84.6msだった。
同じ合成器の母音核からMIDIを作っており、正確なMIDIを与えた結合動作試験である。実歌唱8言語の精度検証とは区別する。
歌唱による連結・省略・リエゾン、短語の言語判定、音節化の曖昧さは残る。
数値表記は実際に歌う読みへ書き換える必要がある。未対応の文字体系・数値を含む場合は、黙って歌詞から除かずエラーにする。
英語の同綴異音語は辞書の先頭候補を使う。未知語はモデル推定、未知の大文字略語は字名読みとする。
欧州言語・韓国語は規則ベースなので外来語・固有名詞・形態素境界をまたぐ発音などに限界がある。
中国語はpypinyinの語句読みを使い、ピンイン1音節を複数の母音文字に分割しない。
97件のテストと8件の言語別サブテストを実施。音素変換中の外部プロセス・ネットワーク・eSpeak importを禁止するテストも含む。

## 依存関係

G2Pは言語ごとのローカル変換器を利用する。`LocalG2P` の出力を共通の音節・近似音素列へ接続する。

| 言語 | 変換器 | ライセンス |
|---|---|---|
| 日本語 | 既存のfugashi / UniDic読み変換 | 従来どおり |
| 英語 | 同梱CMUdict＋g2pEのNumPy推論 | BSD-style / Apache-2.0 |
| 中国語（普通話） | pypinyin 0.55.0＋Epitranのピンイン変換規則 | MIT |
| 独・仏・西・伊・韓 | Epitran 1.35.2＋音節化の補助規則 | MIT |

eSpeak NG / espeakng-loader / phonemizer / g2pK / gruut は本番依存に含めない。
Epitranはパッケージ内の変換表と前後処理だけを使用し、Fliteや外部辞書のダウンロードには進まない。
libmarisaはBSD-2-ClauseとLGPLの選択ライセンスで、BSD-2-Clause側を利用する。
英語辞書・モデルはwheelに同梱し、初期化時にSHA-256を確認する。
JSONは各音節の `pronunciation_source` / `pronunciation_variants` と、`meta` のバージョン・変換器版を記録する。
ライセンス全文・固定revisionは [同梱リソース](../utalign/multilingual/resources/README.md) を参照。

言語判定はLinguaを利用する。Python 3.11はLingua 2.1.1、3.12以降は2.2.0を依存ロックへ記録している。
音響モデル導入後、解析中に音声・歌詞を外部送信しない。
依存パッケージと配布元は [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) を参照。
