# 歌詞文字単位タイミング抽出ツール 実装計画 (utalign)

> 歴史的文書。当初の MMS_FA (CC BY-NC) と ffmpeg は、その後 Apache-2.0 の日本語 CTC モデルと
> libsndfile / afconvert に置き換えた (現状は README.md を参照)。

## 0. 目的

ボーカルトラック MP3・歌詞テキスト・ボーカル MIDI の 3 つを入力に、
歌詞の **各文字の発音開始・終了時刻** を出力するツールと、その結果を
音声再生しながら視覚的に確認できる GUI を作る。

## 1. 素材の実態（調査済み）

| 素材 | 内容 |
|---|---|
| `無限玩具箱ボーカル.mp3` | 3:35.2、48kHz ステレオ、ボーカルのみ（アートワーク付き） |
| `無限☆おもちゃ箱歌詞.txt` | 32 行、全角スペース区切り、括弧記号や「！」「・」「☆」等を含む |
| `無限☆おもちゃ箱.mid` | 480 tpb、テンポ 1 つ（106 BPM）、ノート 605 個。トラック 1〜4 が **時間的に重ならないセクション**（19–76s / 82–140s / 154–195s / 201–212s）。単旋律だがトラック内に 1〜2 個の微小な重なりあり。歌詞メタイベントなし。 |

観察された性質:
- MIDI は「1 ノート ≒ 1 モーラ」が基本だが、メリスマ（1 モーラを複数ノートで歌う）や
  「っ」「ん」「ー」が独立ノートを持たないケースがあり、ノート数 ≠ モーラ数。
- MIDI の絶対時刻と音声の絶対時刻には未知のオフセットがありうる（要計測）。
- 歌詞には歌われない記号（☆ ・ ！ 括弧 タグ 等）が混在しうる前提で設計する。

## 2. 全体アーキテクチャ

```
歌詞 txt ─→ [A] 歌詞正規化・モーラ化 ─→ モーラ列 (各モーラ→元文字インデックス群)
                                             │
音声 mp3 ─→ [B] CTC 強制アライメント ─────→ モーラ毎の音声推定時刻 (onset/offset, score)
                                             │
MIDI     ─→ [C] ノート抽出・オフセット補正 ─→ ノート列 (onset/offset/pitch)
                                             │
             [D] モーラ↔ノート DP 対応付け ──→ モーラ毎の確定時刻 (MIDI 精度)
                                             │
             [E] 文字へ展開・JSON 出力 ──────→ result.json / result.csv
                                             │
             [F] GUI (ブラウザ) ────────────→ 波形 + ピアノロール + 文字ボックス + 再生
```

### [A] 歌詞正規化・モーラ化
1. 行ごとに読み込み。`[...]`, `(...)`, `（...）`, `<...>`, `【...】` などのタグ・括弧内は
   「非発音」として扱う（設定で切替可）。
2. 記号（☆ ・ ！ ？ 、 。 ー以外の長音記号 等）と空白は非発音。ただし「・」で区切られた
   「タ・タ・タ」「た・か・ら・も・の」は各文字が発音される。
3. 漢字→読み: `fugashi` + `unidic-lite`（MeCab）で形態素ごとの発音（pron）を取得。
   ひらがな・カタカナはそのまま。「モニゅっと」「キュルっと」のような造語も
   文字単位フォールバックで処理。
4. 読みをモーラに分割（拗音「きゃ」は 1 モーラ、「っ」「ん」「ー」は独立モーラ扱いだが
   フラグを持つ）。各モーラは **元テキストの文字インデックス集合** を保持する。
   漢字 1 文字が複数モーラ（例: 景色=け・し・き）の場合は、そのモーラ群を
   形態素内の漢字文字へ按分して割り当てる（按分は文字数比、辞書に単漢字読みがあれば優先）。
5. モーラ→ローマ字（MMS_FA が受け付ける小文字ラテン文字）を生成。

### [B] 音声側: CTC 強制アライメント
- `torchaudio.pipelines.MMS_FA`（Meta MMS の多言語 wav2vec2 CTC アライナ、ローマ字入力）を用い、
  16kHz モノラル化した音声に対して全モーラのローマ字列を強制アライメント。
- 出力: モーラ毎の推定開始/終了（20ms フレーム精度）と尤度スコア。
- 歌唱ではロングトーンの終了時刻が CTC では不正確なため、**開始時刻と信頼度**を主に使う。
- 長尺（3.5 分）なので、MIDI トラック境界の無音区間を利用し **セクション単位で分割**して
  アライメントする（メモリと精度の両面で有利）。セクションごとの歌詞行の割当は、
  全体アライメントの粗い結果（または行数按分）から決める。
- 補助: `faster-whisper` による ASR は「歌詞にあるが歌われていない行」の検出や
  デバッグ用の参考情報として任意実行（必須ではない）。

### [C] MIDI 側
- `mido` でテンポマップを考慮して秒に変換。全トラックをマージし、
  発音ノート列（onset, offset, pitch）を時刻順に得る。
- 重なりは「次のノート onset で前のノートを切る」で単旋律化。
- **MIDI↔音声オフセット推定**: 音声のオンセット強度（librosa）と MIDI ノートオンの
  インパルス列の相互相関でグローバルオフセットを推定。さらに [B] の結果との
  中央値差分で微調整（セクションごとに独立推定して DAW 書き出しずれにも対応）。

### [D] モーラ↔ノート対応付け（本ツールの中核）
- 単調な DP（動的計画法）で、モーラ列 M とノート列 N を対応付ける。
  - 遷移: (1) モーラ i をノート j に割当（コスト = |audio_onset(i) − note_onset(j)| を
    信頼度で重み付け） (2) ノート j をメリスマとして直前モーラに追加（コスト小、
    ただし音声で新モーラ開始が検出された場合は大） (3) モーラ i をノートなしで
    直前ノートに相乗り（「っ」「ん」「ー」は低コスト、それ以外は高コスト）
    (4) モーラ i を「未歌唱」としてスキップ（高コスト。タグ除去漏れ・歌われない行対策）。
- 結果: 各モーラの確定 start = 割当先ノートの onset、end = 割当ノート群の最後の offset。
  「っ」「ん」等の相乗りモーラは、相乗り先ノート内を音声のエネルギー/CTC 境界で分割。
- 品質指標: モーラごとに audio と MIDI の onset 差、CTC スコア、スキップ有無を記録し、
  GUI で色分け表示。

### [E] 出力
- `result.json`: 
  - `chars`: 元テキスト全文字（改行・空白・記号含む）に対し
    `{index, char, line, start, end, sung(bool), mora_ids, confidence}`
  - `moras`: `{id, kana, romaji, start, end, note_ids, audio_start, audio_end, score}`
  - `notes`: `{id, start, end, pitch, mora_ids}`
  - `meta`: オフセット値、パラメータ、素材ファイル名
- `result.csv`（文字単位）も併せて出力。
- CLI: `python -m utalign align --audio ... --lyrics ... --midi ... --out result.json`

### [F] GUI
- 依存を抑えるため **ブラウザベース**（単一 HTML + JS、`python -m utalign serve` で
  ローカル配信）。
- 表示: 波形（上）/ MIDI ピアノロール（中）/ 文字ボックスのタイムライン（下）を同一時間軸で
  表示、再生ヘッド追従・ズーム・クリックでシーク。右側または下部に歌詞全文を表示し、
  再生中の文字をカラオケ風にハイライト。低信頼・スキップ文字は色分け。
- 再生: `<audio>` 要素で MP3 をそのまま再生（Web Audio でピークデータを描画）。
- 手修正機能はスコープ外（初期版）。ただしモーラ境界のドラッグ編集は将来拡張可能な
  データ構造にしておく。

## 4. 作業ステップと検証

1. `utalign/lyrics.py`: 正規化・モーラ化。**検証**: 全行のモーラ列を目視、非発音記号の除外確認。
2. `utalign/midi.py`: ノート抽出。**検証**: 605 ノート、セクション境界一致。
3. `utalign/audio_align.py`: MMS_FA 実行。**検証**: 行頭モーラの開始時刻が MIDI フレーズ開始と
   ±0.3s 以内に収まる割合を確認。
4. `utalign/offset.py`: オフセット推定。**検証**: 相互相関ピークと CTC 差分中央値の一致。
5. `utalign/matcher.py`: DP 対応付け。**検証**: 未割当ノート数・スキップモーラ数・onset 差分分布。
6. `utalign/cli.py` + 出力。
7. `gui/` 実装 → `serve` で起動し、ブラウザで再生・ハイライトが同期することを実動確認。
8. README 整備。

## 5. リスクと対策

| リスク | 対策 |
|---|---|
| 漢字の読み誤り（歌詞特有の当て字） | 読み辞書ファイル（`readings.override.txt`）で上書き可能に |
| CTC が歌唱に弱く大きくずれる | セクション分割 + MIDI が最終時刻の根拠なので CTC は「どのノートか」の判別にのみ使用 |
| ノート数とモーラ数の乖離（メリスマ/相乗り） | DP に明示的な遷移として組込み、コストを調整可能に |
| MIDI と音声のオフセット | 相互相関 + セクション毎推定 |
| 歌われない行・タグ | 括弧/タグ除去 + DP のスキップ遷移 + GUI で可視化 |
| 漢字複数モーラの文字按分 | モーラ単位の結果も出力し、文字単位は按分ルールを明記 |

## 6. 実測結果（計画の前提確認、2026-09-15）

- **MIDI↔音声オフセット**: オンセット強度と MIDI ノートオンの相互相関で、全 4 セクションとも
  音声が MIDI より **約 +0.10〜0.12 s 遅れ**（ピーク明瞭）。グローバル 1 値で十分だが
  セクション別推定も実装する。
- **MMS_FA の実用性**: セクション 1（60 s, 233 モーラ）を Apple M5 CPU で約 4 s で処理
  （モデル初回 DL 約 2 分、以降キャッシュ）。モーラ開始時刻は MIDI/音声オンセットと
  ±0.1 s 程度で整合し、行頭で破綻なし。
- **ノート数 < モーラ数**: セクション 1 は 205 ノートに対し 233 モーラ（っ除く）。
  ピッチ解析（pyin）で確認すると、冒頭の 8 分音符 1 つ（D#4）に「ひ・き」の 2 モーラが
  乗っており、MIDI は歌唱をやや簡略化した採譜である。したがって [D] の DP では
  「1 ノートに複数モーラ」を「っ/ん/ー」に限らず **一般的な遷移**として扱い、
  ノート内の分割位置は CTC のモーラ開始時刻（および音声オンセット）で決める。
  逆に「1 モーラに複数ノート（メリスマ）」も存在しうるため両方向を許す。
- fugashi + unidic-lite の読み（pron）は全 32 行で妥当（は→ワ、鼓動→コドー 等）。
  「モニゅっと」「キュルっと」のような造語は形態素が分断されるが、読みをカナ列に
  連結してからモーラ分割するため問題ない。

## 7. Opus レビュー反映（2026-09-15）

レビューで挙がった 17 項目のうち、計画を変更するものを以下に確定する。

### 時刻の根拠（階層化）
- MIDI は IOI の 84% が 1/16・1/8 グリッドに量子化された「スコア時刻」であり、フレーズ内の
  ノート位置は機械的に決まっている。そのため最終時刻は次の階層で決める。
  - フレーズ先頭モーラ: `MIDI onset + offset`
  - フレーズ内モーラ: `clip(CTC onset, MIDI onset + offset ± 0.10s)`（CTC 欠損時は MIDI）
  - 1 ノートを複数モーラで共有: 先頭は上記、2 番目以降は CTC onset をノート区間内にクランプ
  - メリスマ（1 モーラ複数ノート）: 先頭ノートの onset
  - end: 同一フレーズ内なら「次モーラの start」、フレーズ末は最後のノートの offset（cap 付き）。
    JSON に `end_kind` を持たせる。CTC の offset は使わない。
- JSON には `midi_start / ctc_start / start / source` を全て残す。

### DP の定式化
- 状態 (i, j)、遷移は ① 1:1 ② 1 ノート→k モーラ (k≤3) ③ 1 モーラ→l ノート (l≤4)
  ④ モーラ skip ⑤ ノート skip の 5 種。②は `note_dur / k < 0.09s` で大ペナルティ。
- 主コストは CTC 残差 `|ctc_onset(i) − (note_onset(j)+offset)|`（CTC スコアで重み付け）。
  ノート数/モーラ数の辻褄合わせは弱い正則化のみ。
- レビューでは二段（フレーズ DP → モーラ DP）が提案されたが、本実装では **全曲を 1 回の
  CTC アライメントで絶対時刻付け**し、その CTC 時刻を主コストとする単一のモーラ DP とする。
  CTC の絶対時刻がアンカーとして働くため誤りの下流伝播は起きにくく、二段構成の
  「歌詞セグメント↔MIDI フレーズ」対応は不要になる（フレーズ情報は出力 `phrases[]` として集計）。
  もし残差指標が悪ければ二段化する。

### CTC アライメントの単位
- 音声は **約 20s の固定窓 + 前後 2s のオーバーラップ**で emission を計算し、窓の中央部分を
  連結して全曲分の emission 行列を得る（wav2vec2 の O(T²) メモリ回避と、歌詞割当の
  鶏卵問題の回避を両立）。forced_align は全曲・全モーラで 1 回。emission は
  `work/` にキャッシュする。alignment は CPU で実行（MPS カーネルなし）。
- 行境界・セグメント境界に `<star>` トークンを挿入し、歌詞にない発声や息継ぎを吸収する。
- ローマ字化: 長音「ー」は前モーラの母音に畳み、促音「っ」はトークンを出さない
  （モーラ層では独立モーラとして保持し、多対一で CTC ユニットに対応付ける）。
  「ん」は `n` 1 文字、母音の前では `n'` を試す。

### 歌詞正規化・読み
- 非発音判定は POS ではなく **文字クラス**（記号ホワイトリスト + 括弧/タグ内）で行う。
- かな のみの形態素は表層を直接モーラ分割し、`pron` のモーラ数が一致する場合のみ
  `pron`（は→ワ 等）を採用。漢字を含む形態素は `pron` を使い、
  **送り仮名の後方一致**で漢字部分のモーラを切り出す（景色/楽しい 等の反例を回避）。
  複数漢字に複数モーラが残る場合は `readings.override.txt` → 文字数比按分 + `split_estimated` フラグ。

### オフセット
- 相互相関は探索 ±0.5s に制限し、CTC 残差中央値と ±40ms で一致することを確認する。
  残差の一次回帰の傾きが 1±0.001 から外れる場合はドリフト警告を出す。

### 検証器と指標
- `click` コマンド: 各モーラ start にクリック音を重畳した WAV を出力（耳で判定）。
- 教師なし指標: ①繰り返し行（3 回出るサビ等）の割当パターン一致率 ②CTC 残差の中央値・
  90 パーセンタイル・>150ms 比率 ③skip されたモーラ数/ノート数。

### GUI
- 再生は MP3 ではなく **ffmpeg でデコード済みの WAV** を配信（エンコーダディレイ差の回避）。
  グローバルオフセットのスライダを置く。
- ハイライトは `requestAnimationFrame` + `audio.currentTime`。波形は Python 側で
  事前計算した `peaks.json`。ファイル名は `encodeURIComponent`。

### 初版から削除
- faster-whisper（`<star>` で代替）、エネルギーによるノート内分割、CSV 出力、
  ドラッグ編集用データ構造。

### 追加
- `lines[]` / `phrases[]` 集計出力、emission キャッシュ、`end_kind`。

## 8. 実装状況 (2026-09-15)

計画 1〜7 章の内容を `utalign/` として実装し、対象曲で実動確認済み。使い方と result.json のスキーマは README.md を参照。
実装時に追加した点: ノート区間の音声エネルギー (有声/無声) を DP コストに反映 (無音ノートは skip しやすく、
無音ノートへのメリスマは抑制)、メリスマの休符またぎペナルティは休符長に比例、共有ノート内のモーラ位置は
次ノート開始まで許容 (MIDI の量子化された終端に縛られない)。
